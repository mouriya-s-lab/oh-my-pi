# 登记

负责记下归属单位的嵌套树、每个单位名下尚未释放的受管进程树，以及每个单位是否已经触发过超限告警；不负责起进程、终止进程、读用量，也不负责计算读数是否超限。

## 为什么

单独成为子模块：台账只用到父模块的进程树身份与归属单位身份，不需要平台的任何连接；平台也不需要知道哪棵受管进程树属于哪个归属单位。单位嵌套、进程树归属与已告警单位集合放在同一个模块，因为它们共守"登记在册的内层单位、受管进程树与已告警标记都属于一个活着的单位"这条不变量（``Registry`Table``）。

只记受管进程树（`trees : map Identity to UnitId`），不把树里的后代进程逐个抄进台账，也不分"有围栏"与"无围栏"两套账本：每棵受管进程树在 ``Platform`Spawn`` 时产生唯一的根身份，计量与终止都直接对这棵树操作；某个平台上怎样用进程组或环境标记把树内后代收齐，是 ``Platform`` 的内部实现。起源进程先退出而子孙进程仍在树里运行时，这棵树的身份照样留在单位名下，直到收尾经 ``Registry`Release`` 释放。

告警去重记在归属单位上（`alerted : set of UnitId`），不记在单个子进程上：一次工具调用或会话在存续期内可能连续派生多个子进程，按单个子进程去重会在每次新起子进程越过阈值时重复告警；按归属单位记录已告警状态，同一个归属单位在存续期内至多触发一次告警，单位结束时随单位一起清掉。

归属单位是一棵无环森林，架构不规定固定层数：宿主、会话、工具调用是业务对单位的细化，架构只要求内层在外层之内开始、外层结束前内层已全部结束且名下受管进程树已全部释放。

## 语义

台账与平台运行在同一个宿主进程内；宿主崩溃时台账消失。

单位由 ``Registry`Begin`` 开始，由 ``Registry`End`` 结束；``End`` 要求内层子单位（``Registry`Children``）已全部结束、名下受管进程树（``Registry`Trees``）已全部释放，并一并清除该单位的已告警记录。

进程树在平台上释放的事实来自 ``Platform`Kill``，``Registry`Release`` 是台账跟上事实；调用两次与一次效果相同。
