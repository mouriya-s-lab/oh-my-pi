# 登记

负责记下宿主起的每个进程属于哪个归属单位、承诺活多久、归属依据是什么，以及归属单位的开始与结束；不负责读用量，不负责决定阈值与告警。

## 为什么

归属单位与进程登记放在同一个模块，因为它们共享"登记在册的进程都属于一个活着的单位"这条不变量（``Registry`Table``）；单独成为子模块，因为它只用到父模块的身份、围栏与起进程连接，父模块不需要知道谁属于谁。

归属单位分宿主、会话、一次工具调用三层，外层结束前必须先结束全部内层：收尾顺序由嵌套决定，不由谁先发现谁决定。

寿命承诺由起进程的一方在登记时给出，不由登记方事后推断：只有起进程的一方知道这是会话自己的进程、多个宿主共用的守护进程，还是用户有意放走的进程。承诺不随单位结束的进程不得进入围栏，这样 ``Platform`Kill`` 永远不会误伤它们。

归属依据分三支：宿主亲手起的（`<Spawned>`）、`exclusive` 围栏收纳的（`<Enclosed>`）、从进程表或环境标记推断的（`<Inferred>`）。只有前两支可以被单位收尾时终止；推断出来的只记录、只计量，不终止。不让推断出来的进程也能被终止：推断可能把别人的进程算成自己的，终止的代价不可逆。

## 语义

宿主单位在宿主进程启动时开始、退出时结束；它结束时按 ``Platform`Guarantee`` 处理自己的围栏：`<Cooperative>` 时先 ``Platform`Kill`` 再退出，`<Kernel>` 时退出即可。宿主崩溃时 ``Registry`` 的状态随之消失，内核保证之外的成员无人清理。

一个单位开始时沿用外层单位的围栏；``Registry`Fence`` 之后它与之后开始的内层单位用新围栏。围栏由开它的单位在结束时 ``Platform`Kill`` 并 ``Platform`Close``；沿用外层围栏的单位结束时只终止自己登记的、可终止的进程。

``Registry`Adopt`` 只在围栏 `inescapable` 或 `exclusive` 时有意义；被收纳的进程继承 `<Owned>` 承诺。推断出来的进程经 ``Registry`Observe`` 登记为 `<Released>`。

进程退出的事实来自平台，``Registry`Drop`` 只是记录方跟上事实。
