# 登记

负责记下归属单位的嵌套、替每个单位盖的标记，以及每个进程带哪个标记、怎样被认出、在哪个围栏里；不负责起进程、终止进程、读用量。

## 为什么

单独成为子模块：台账只用到父模块的身份、标记与围栏类型，不需要平台的任何连接；平台也不需要知道谁属于谁。单位树、标记与进程登记放在同一个模块，因为它们共守"每条登记的标记都是替某个活着的单位盖的"这条不变量（``Registry`Table``）。

归属经标记传递，登记里不存单位：一次 ``Registry`Claim`` 替一个单位盖一个标记，用它起的进程与它的后代都带这个标记，所以"属于哪个单位"由标记查出。不在每条登记里复制单位：复制之后围栏里发现的后代要由登记方再去猜它属于谁，而标记已经是事实。

同一围栏里的进程共用标记：围栏随一次 spawn 诞生，围栏里的后代继承那次 spawn 的环境。这条不变量让围栏里发现的进程归属唯一。

归属单位是一棵森林，架构不规定层数：宿主、会话、工具调用是业务对单位的细化，架构只要求内层在外层之内开始、外层结束前内层已全部结束。`parent` 无环写进不变量：有环的单位永远不能结束。

没有寿命承诺：宿主起的进程一律随它的单位结束而终止（依据见父模块）。所以 ``Registry`End`` 要求名下没有登记，而不是"没有可终止的登记"。

## 语义

台账与平台运行在同一个宿主进程内；宿主崩溃时台账消失。

单位由 ``Registry`Begin`` 开始，由 ``Registry`End`` 结束；``End`` 要求内层已全部结束、名下没有登记。清掉登记的次序由业务决定：先对 ``Registry`Enclosures`` 里的每个围栏 ``Platform`Kill``，再对围栏外的登记按身份 ``Platform`Terminate``，`contained` 为假的平台上还要先用 ``Platform`Marked`` 把离开围栏的后代找回来登记；都发生后经 ``Registry`Drop`` 让台账跟上事实。

进程退出的事实来自平台，``Registry`Drop`` 只是台账跟上事实；撤销两次与一次效果相同。

``Registry`Claim`` 盖的标记在单位结束时作废；作废后平台上可能还有带它的进程（崩溃后残留、读不到环境的逃逸者），本设计不再认它们。
