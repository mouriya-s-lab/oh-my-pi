# 平台

负责陈述操作系统的事实：开围栏、起进程、列成员、推断后代、读用量、终止进程与围栏；不负责决定哪些进程属于谁、承诺活多久，也不负责告警。

## 为什么

单独成为子模块：三个操作系统各自实现这一个模块就互换，父模块只需要它们共用的身份、围栏与读数类型，不需要知道围栏在某个平台上是进程组、cgroup 还是作业对象。

状态里有 `charged`（已退出成员留在围栏里的累计用量）：`aggregate` 的围栏读数含已退出成员，这个事实只有平台知道，``Platform`Measure`` 按能力决定要不要把它算进去。

``Platform`Related`` 是推断：按父子关系或宿主留下的标记找出与锚点有关的活着的进程。推断可能把别人的进程算进来，所以它的结果只能作为 ``Registry`Membership`` 里 `<Inferred>` 的来源，不能直接终止。

## 语义

进程可以在任何连接之外出生或退出：围栏里的进程自行派生后代时，后代成为同一围栏的成员；进程自行退出时，它离开 `alive` 与所在围栏的成员集，用量计入该围栏的 `charged`。这些变化由操作系统引起，不是宿主可以调用的连接，所以不写成操作；宿主经 ``Members``、``Related`` 与 ``ProbeAll`` 事后得知，三者的结果都是取回那一刻的副本。

``Platform`Abandon`` 是宿主退出前对自己围栏的处置：`<Kernel>` 保证的围栏什么都不做，内核会在宿主死后终止成员；`<Cooperative>` 的围栏先终止全部成员再关闭。宿主崩溃时 ``Abandon`` 不会被调用。

``Platform`Open`` 在宿主已处于外层容器时可能不可用；不可用不是失败，使用方按无围栏继续。
