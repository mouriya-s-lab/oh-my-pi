# 登记

负责记下归属单位的嵌套、每个单位名下尚未撤销登记的受管进程树，以及每个单位存续期内是否已经触发过超限告警。不负责起进程、终止进程、读用量，也不负责判定读数是否超限。

## 依据

同一归属单位在存续期内会反复派生子进程、被多次采样，按单个子进程告警会重复刷屏（来源：上游 #5684、#12961，证据见附录 `evidence/upstream-issues.md`）。所以 ``Registry`Table.alerted`` 按单位记录是否已告警，随 ``Registry`End`` 清除。

## 为什么

单独成为子模块：台账怎样记归属可以对平台隐藏，平台换实现时台账不变。单位嵌套、树的归属与已告警标记放在同一个模块，因为它们共守 ``Registry`Table`` 的同一条不变量。

只记受管进程树，不把树里的后代逐个抄进台账：计量与终止都直接对树操作，后代怎样收齐是 ``Platform`` 的实现。起源进程先退出而后代仍在运行时，树照样留在单位名下，直到经 ``Registry`Release`` 撤销。

已告警事实放在台账而不是业务里：它是单位存续期内的事实，与单位同生同灭；用什么阈值、何时触发或抑制是 `business/host/` 的判定。

不规定单位的层数：宿主、会话、工具调用怎样分层由业务决定。

## 语义

台账与平台运行在同一个宿主进程内；宿主崩溃时台账消失。

平台上的树已释放这一事实来自 ``Platform`Kill``；``Registry`Release`` 只让台账跟上，调用方必须先终止再撤销。
