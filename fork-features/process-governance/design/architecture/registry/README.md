# 登记

负责记下归属单位的嵌套、每个单位名下的围栏，以及每个单位名下没有围栏的进程；不负责起进程、终止进程、读用量。

## 为什么

单独成为子模块：台账只用到父模块的身份、单位与围栏类型，不需要平台的任何连接；平台也不需要知道哪个围栏或进程属于哪个单位。单位树、围栏归属与无围栏进程归属放在同一个模块，因为它们共守"登记在册的围栏与无围栏进程都属于一个活着的单位"这条不变量（``Registry`Table``）。

围栏与无围栏进程分开登记，围栏不挂在进程身份身上：有围栏时，计量与终止都直接对围栏操作，围栏里派生的孙进程不需要逐个抄进台账；起源进程（如 shell）先退出时，围栏照样留在单位名下，直到单位收尾经 ``Registry`Release`` 释放。只有起进程时没要围栏或没开出围栏的进程，才以 ``Registry`Track`` 记在 `unfenced` 里，收尾时按身份逐个终止。

不在台账里存"进程是怎样被宿主认出来的"：观测路径不是台账状态；`contained` 为假的平台上按单位身份从环境里补找出来的逃逸后代，由业务直接读数或终止，不需要为了终止它先往台账里写一笔再撤销。

归属单位是一棵森林，架构不规定层数：宿主、会话、工具调用是业务对单位的细化，架构只要求内层在外层之内开始、外层结束前内层已全部结束。`parent` 无环写进不变量：有环的单位永远不能结束。

没有寿命承诺：宿主起的进程一律随它的单位结束而终止（依据见父模块）。所以 ``Registry`End`` 要求名下没有围栏也没有无围栏进程。

## 语义

台账与平台运行在同一个宿主进程内；宿主崩溃时台账消失。

单位由 ``Registry`Begin`` 开始，由 ``Registry`End`` 结束；``End`` 要求内层已全部结束、名下没有围栏也没有无围栏进程。收尾的次序由 `business/host/` 的场景承载。

围栏释放与进程退出的事实来自平台，``Registry`Release`` 与 ``Registry`Drop`` 只是台账跟上事实；调用两次与一次效果相同。
